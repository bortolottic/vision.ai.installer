Operations ​

Reference for whoever administers the install: services, ports, GPU, HTTPS and backup.

Stack services ​

The vision-ai stack has fifteen services. Check with:

bash
docker service ls
docker stack ps vision-ai --no-trunc   # the ERROR column explains a 0/1
ServiceWhat it does
nginxEntry point (9080) — routes /api, /ws, /hls, /webrtc, /mcp and /
hubThe UI (Vue SPA)
apiThe engine; runs migrations at startup
ingestCaptures the camera video
inferInference (detection)
rulesRules engine
notifyNotification delivery
aggregatorPersists detection (history)
trainerTraining worker
mcpMCP server
mediaVideo gateway (MediaMTX)
dbTimescaleDB
redisCache, frames, leases
brokerQueues (RabbitMQ)
objectsObject store (MinIO)

GPU ​

For inference and training to use an NVIDIA GPU:

  1. Install the NVIDIA Container Toolkit and confirm:
    bash
    docker run --rm --gpus all nvidia/cuda:12.6.0-base-ubuntu24.04 nvidia-smi
  2. In the node's /etc/docker/daemon.json, advertise the resource and restart Docker:
    json
    { "default-runtime": "nvidia", "node-generic-resources": [ "NVIDIA-GPU=0" ] }
  3. Deploy with --gpu:
    bash
    cd /tmp/vision-ai/vision-ai && . deploy/deploy.sh --gpu vision-ai .env.production

With two cards, use VISION_TRAINER_DEVICE=cuda:1 so training does not steal frames from inference.

HTTPS ​

bash
cd /tmp/vision-ai/vision-ai
./deploy/scripts/prepare-ssl.sh /path/to/certificate.pfx
. deploy/deploy.sh --ssl vision-ai .env.production

The platform then serves at https://<host>/; port 9080 redirects to HTTPS.

Secrets ​

On the first install secrets are generated automatically and written to .env.production (mode 600). Back it up. Changing VISION_SECRET_KEY after cameras exist makes their passwords unreadable — the bootstrap does not rotate it if the database already exists.

Backup ​

Data lives in Docker volumes. The database, for example:

bash
docker run --rm -v vision-ai_db_data:/data -v $(pwd):/backup \
  alpine tar czf /backup/db_backup.tar.gz /data

Other volumes: broker_data, object_data, model_cache, exports_data. Removing them deletes the data.

Upgrading ​

Run the installer pointing at the new tag, or set IMAGE_TAG in .env.production and run ./deploy_production.sh again. Swarm updates service by service, with automatic rollback on failure.
