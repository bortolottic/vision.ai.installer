Operación ​

Referencia para quien administra la instalación: servicios, puertos, GPU, HTTPS y respaldo.

Servicios del stack ​

El stack vision-ai tiene quince servicios. Verifique con:

bash
docker service ls
docker stack ps vision-ai --no-trunc   # la columna ERROR explica un 0/1
ServicioQué hace
nginxPunto de entrada (9080) — enruta /api, /ws, /hls, /webrtc, /mcp y /
hubLa interfaz (SPA Vue)
apiEl motor; ejecuta las migraciones al arrancar
ingestCaptura el video de las cámaras
inferInferencia (detección)
rulesMotor de reglas
notifyEntrega de notificaciones
aggregatorPersiste la detección (historial)
trainerWorker de entrenamiento
mcpServidor MCP
mediaGateway de video (MediaMTX)
dbTimescaleDB
redisCaché, cuadros, leases
brokerColas (RabbitMQ)
objectsAlmacén de objetos (MinIO)

GPU ​

Para que la inferencia y el entrenamiento usen una GPU NVIDIA:

  1. Instale el NVIDIA Container Toolkit y confirme:
    bash
    docker run --rm --gpus all nvidia/cuda:12.6.0-base-ubuntu24.04 nvidia-smi
  2. En el /etc/docker/daemon.json del nodo, anuncie el recurso y reinicie Docker:
    json
    { "default-runtime": "nvidia", "node-generic-resources": [ "NVIDIA-GPU=0" ] }
  3. Levante con --gpu:
    bash
    cd /tmp/vision-ai/vision-ai && . deploy/deploy.sh --gpu vision-ai .env.production

Con dos tarjetas, use VISION_TRAINER_DEVICE=cuda:1 para que el entrenamiento no le robe cuadros a la inferencia.

HTTPS ​

bash
cd /tmp/vision-ai/vision-ai
./deploy/scripts/prepare-ssl.sh /ruta/del/certificado.pfx
. deploy/deploy.sh --ssl vision-ai .env.production

La plataforma pasa a atender en https://<host>/; el 9080 redirige a HTTPS.

Secretos ​

En la primera instalación los secretos se generan automáticamente y se escriben en .env.production (permiso 600). Respáldelo. Cambiar VISION_SECRET_KEY después de que haya cámaras registradas vuelve ilegibles sus contraseñas — el bootstrap no lo rota si la base de datos ya existe.

Respaldo ​

Los datos viven en volúmenes de Docker. La base de datos, por ejemplo:

bash
docker run --rm -v vision-ai_db_data:/data -v $(pwd):/backup \
  alpine tar czf /backup/db_backup.tar.gz /data

Otros volúmenes: broker_data, object_data, model_cache, exports_data. Eliminarlos borra los datos.

Actualizar la versión ​

Ejecute el instalador apuntando a la nueva etiqueta, o ajuste IMAGE_TAG en .env.production y ejecute ./deploy_production.sh de nuevo. Swarm actualiza servicio por servicio, con rollback automático ante fallos.
