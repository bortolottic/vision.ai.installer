Operação ​

Referência para quem administra a instalação: serviços, portas, GPU, HTTPS e backup.

Serviços da stack ​

A stack vision-ai tem quinze serviços. Confira com:

bash
docker service ls
docker stack ps vision-ai --no-trunc   # a coluna ERROR explica um 0/1
ServiçoO que faz
nginxPorta de entrada (9080) — encaminha /api, /ws, /hls, /webrtc, /mcp e /
hubA tela (SPA Vue)
apiO motor; roda as migrações na partida
ingestCaptura o vídeo das câmeras
inferInferência (detecção)
rulesMotor de regras
notifyEntrega das notificações
aggregatorPersiste a detecção (histórico)
trainerWorker de treino
mcpServidor MCP
mediaGateway de vídeo (MediaMTX)
dbTimescaleDB
redisCache, frames, leases
brokerFilas (RabbitMQ)
objectsArmazém de objetos (MinIO)

GPU ​

Para a inferência e o treino usarem uma placa NVIDIA:

  1. Instale o NVIDIA Container Toolkit e confirme:
    bash
    docker run --rm --gpus all nvidia/cuda:12.6.0-base-ubuntu24.04 nvidia-smi
  2. No /etc/docker/daemon.json do nó, anuncie o recurso e reinicie o Docker:
    json
    { "default-runtime": "nvidia", "node-generic-resources": [ "NVIDIA-GPU=0" ] }
  3. Suba com --gpu:
    bash
    cd /tmp/vision-ai/vision-ai && . deploy/deploy.sh --gpu vision-ai .env.production

Com duas placas, use VISION_TRAINER_DEVICE=cuda:1 para o treino não roubar quadro da inferência.

HTTPS ​

bash
cd /tmp/vision-ai/vision-ai
./deploy/scripts/prepare-ssl.sh /caminho/do/certificado.pfx
. deploy/deploy.sh --ssl vision-ai .env.production

A plataforma passa a atender em https://<host>/; a 9080 redireciona para HTTPS.

Segredos ​

Na primeira instalação os segredos são gerados automaticamente e gravados em .env.production (permissão 600). Faça backup. Trocar VISION_SECRET_KEY depois que há câmeras cadastradas torna as senhas delas ilegíveis — o bootstrap não a rotaciona se o banco já existe.

Backup ​

Os dados vivem em volumes do Docker. Exemplo, o banco:

bash
docker run --rm -v vision-ai_db_data:/data -v $(pwd):/backup \
  alpine tar czf /backup/db_backup.tar.gz /data

Os demais volumes: broker_data, object_data, model_cache, exports_data. Removê-los apaga os dados.

Atualizar a versão ​

Rode o instalador apontando para a nova tag, ou ajuste IMAGE_TAG no .env.production e rode ./deploy_production.sh de novo. O Swarm faz a atualização serviço a serviço, com rollback automático em falha.
